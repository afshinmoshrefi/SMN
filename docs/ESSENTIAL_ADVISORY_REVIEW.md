# Essential checks and advisory review findings

This isolated local candidate implements the owner's instruction that subjective
wording, framing and placement findings must not hold a factually qualified
article. It does not change model settings, original model output, receipts,
TradeWave mathematics, visual approval or publication authorization.

`facts_and_sources`, `history_and_numeric_meaning` and `source_allowances` remain
hard. All factual, temporal, instrument, numeric and unclassified issues remain
hard regardless of severity. Complete source/claim ledgers, exact cited quotes,
captured source custody, immutable model inputs/output, engine assets, mechanical
bindings, security checks and actual separate visual approval remain required.

The legacy `smn_identity_and_visuals` checkbox combines identity with placement
preferences. A failed checkbox is advisory only after the gate verifies SMN's
native brand markup and the exact TradeWave study URL, statistics, figures and
explanations using existing renderer fragments and native asset validators.
This deterministic essential identity proof is not a model or pixel approval.

The review-render hash is reconstructed with the stock held renderer from the
exact immutable article/bundle/chart/hero/seasonal context. It remains stable
through stock finalization's navigation, footer and generation metadata changes.
Final rendered HTML retains its separate exact existing review-binding hash;
native figures and every reviewed text unit are checked against that current HTML.
No disposition hash is rewritten after finalization.

Coverage findings remain hard by default. A legacy finding may be classified by
an explicit independent AI review in `editorial-advisory-disposition.json` beside
the result. This is not a human override or a model receipt. It contains:

- `version: 1`, canonical AI task `actor`, explicit UTC `utc`,
  `human_reviewed: false` and `is_model_receipt: false`;
- exact `article_sha256` (canonical JSON), `review_render_sha256`,
  `context_sha256` (canonical context) and original `review_sha256`;
- `issues`, each with original `index`, exact canonical `issue_sha256`, `kind`,
  `material_item_ids` and a substantive independent-review `reason`.

`presentation_only` requires an empty item-ID list and covered rows for all
required material items. `optional_omission` requires explicit known IDs whose
verified pre-writer material contract says `required: false` and whose audit rows
say `missing`. An incomplete ledger, unknown disposition, required omission or
explicit incorrect/unsupported factual allegation cannot qualify. All exact
quotes and factual/temporal/cohort claim ledgers are still validated afterward.
An unmapped coverage concern stays hard; the gate does not guess from keywords.

The resulting policy-version-3 proof retains every original check and issue,
the original `passed` value and output hash, the disposition record/hash and any
deterministic identity evidence. A later disposition change invalidates the final
review binding. The original AI report is never rewritten as passed. Canonical
task attribution is an audit label, not a claim of authenticated human identity.
Only authorized artifact preparation may supply this review record.

Existing positive-review proof dictionaries and existing style-only policy-2
proofs retain their exact shape and policy version. New policy-3 fields are added
only for the new essential-identity or explicit coverage-disposition path.

The local branch is based on `b61b37f`. No installed b61 code, production
application, model job, shared Git record or receipt is changed. Coordination was
read from local snapshots only under the local-only instruction; no fresh shared
fetch/claim or peer agreement is claimed. Before any integration or deployment,
the owner must reconcile current shared records and obtain new exact-source
qualification/authorization. An approval for b61 does not approve this candidate.
