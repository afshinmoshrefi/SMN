# SMN reader and private revision contract

The reader is a separate Flask application: `gunicorn --bind 127.0.0.1:8091 'reader_app:create_app()'` from `blog`. It imports no administrator guard, dashboard roles or billing authority. Production is outside this development authorization.

Configuration uses `SMN_READER_PRIVATE_ROOT` (default `/var/lib/smn/reader`), `SMN_NEWS_ROOT` (default `/var/www/smn`), and `SMN_READER_CLIENT_ID`, `CALLBACK_URL`, `AUTHORITY_URL`, `SERVICE_KEY`, `ENV`. Callback must be the exact HTTPS reader `/member/callback`; authority must be an HTTPS origin. `ENV` is `dev` or `prod`. The private root cannot overlap any public root; deployments with several document roots must explicitly pass all `PUBLIC_ROOTS` to the factory. No credential values belong in catalog metadata, logs or Git.

Central contract: authorize is POST `/smn-reader/authorize` with WorkOS access-token Bearer and `X-SMN-Reader-Key`; it returns opaque `reader_authority`, `user_id`, `workos_user_id`, `workos_session_id`, `env`, `expires_at`. Other server requests use that authority Bearer plus the same service header. GET `/smn-reader/entitlement` returns `can_read`, grant/reason/access-end/offer fields and all bound identity/environment/session/expiry fields. GET `/account` supplies identity, entitlement, subscription and offer. POST `/logout`, `/checkout` and `/cancel` use the same scope. There are no caller-selected user IDs. The central service verifies dedicated application JWT, verified email and active provider session; the reader rejects cross-subject/session/environment responses. No entitlement cache is used.

Reader cookies (`smn_reader`, host-only, Secure, HttpOnly, SameSite=Lax, path `/`) contain only random session identifiers. PKCE verifier/state and reader authority remain in SQLite beneath private storage. Callback consumes one pending state and rotates the cookie. Logout requires CSRF, consumes local session, revokes central authority and then uses WorkOS's session logout redirect. Mutations require server-stored CSRF; GET never cancels a subscription or logs out. A failed provider call does not grant access or rewrite membership. Public preview remains available while protected bodies/assets fail closed.

## Content-store API

`ContentStore(root, public_roots)` is the adapter. `prepare_revision(canonical, revision, full_html, preview, approval, assets=None, public_asset_ids=None, aliases=None)` writes an immutable private revision without activation. `preview` is the complete derivative object `{content, provenance}`; its provenance revision must match. `approval` contains `passed:true`, the existing canonical-JSON `digest(preview)` as `derivative_sha256`, actual UTF-8 body SHA as `full_html_sha256`, reviewer and reviewed-at timestamp. This approval must come from actual semantic review, not the mechanical P1 result. Assets are a map of validated relative logical names to bytes or explicit paths; only approved raster images may be public. No evidence folder is copied by extension.

`activate_revision(canonical, revision, transaction_id, expected_revision=None)` performs a SQLite transaction, compares the active revision and is idempotent for the exact root publication transaction. Root holds `posts_lock` and its durable publication intent to bridge this pointer with `posts.json`; the store cannot make those two independent files atomic. `resolve(path)`, `read_revision(path, representation='public', revision=None)`, `private_asset_path(path,revision,name,public=False)`, `withdraw(path,transaction_id)` and `inventory()` support root integration. `set_enabled(True)` is a separate root activation gate; registry starts disabled. Prepared revisions are unavailable until active and enabled. Changed private bytes and stale assets are rejected. Withdrawal denies both public/full representations while retaining private revision history.

Preserve the existing catalog URL as canonical. Derivative `provenance.article_id`/source production URL is independent. Register only verified equivalent aliases; the same production study can appear in several editions without collision. An alias redirects to its canonical path; unknown article/asset/editor/static paths return unavailable and never fall back to disk.

`reader_app.asset_url(canonical,revision,name,public=False)` returns scoped `/member/assets?article=...&revision=...&name=...`; the explicit public allowlist uses `/member/public-assets`. Root must rewrite full-body asset URLs to these routes before reviewing/staging the delivered HTML. Public copy uses autoescaped Jinja text and never includes withheld full text in HTML, JSON, metadata or script. Every response currently uses `private, no-store` and `Vary: Cookie`, avoiding authenticated cache contamination or stale membership promises. Edge caches still require real reverse-proxy verification.

## Migration and deployment boundary

`python article_content_migrate.py inventory --public-root <root> --posts <posts.json> --output <new-private-inventory.json>` records all existing file paths/hashes and catalog URL mappings. `prepare --store-root <private-root> --public-root <public-root> --manifest <explicit-reviewed-mapping.json>` stages only the supplied approved revision. Mapping fields are `canonical_path`, `revision`, `full_html_path`, `preview_path`, `approval_path`, `assets`, `public_asset_ids`, `verified_aliases`. Neither command deletes files, auto-extracts previews, rewrites URLs, activates revisions or enables the registry.

Root owns complete old-root inventory, exact asset rewriting, public original removal/archive, publisher/editor adapter wiring and recoverable catalog activation. Nginx must intercept every legacy `/articles/` and `/editions/` variant plus raw evidence/CSV/alternate static routes before static delivery. Reader-only tests cannot certify absence of a legacy proxy bypass. A selected pilot is not complete-corpus migration proof. Enable after negative proxy/cache tests and rollback preparation. Reader sessions and article revision directories must retain owner-only storage permissions.

Focused checks: `python -m unittest tests.test_article_content_store tests.test_reader_auth tests.test_reader_app -v`.
